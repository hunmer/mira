# 素材库文件导入模式

资源库设置中的“文件导入方式”决定手动上传、文件夹扫描和自动同步发现新文件时，文件如何进入素材库。

可选值：

| 模式 | 素材库中的文件 | 源文件 | `files.path` |
| --- | --- | --- | --- |
| `copy`（默认） | 创建完整副本 | 保留 | `NULL` |
| `move` | 先复制到素材库 | 复制成功后移入系统回收站 | `NULL` |
| `link` | 创建链接文件 | 保留 | 保存源文件绝对路径 |

## 配置

在资源库编辑对话框中选择导入方式并保存。配置保存到资源库的 `customFields.importType` 字段。

修改配置后，后续导入请求立即使用新模式，不需要重启服务端。

## 各模式说明

### Copy

适合希望素材库独立保存文件副本的场景。源文件不会被修改，素材库文件删除也不会影响源文件。

### Move

导入流程为：

1. 将源文件完整复制到素材库目标目录。
2. 确认复制成功。
3. 将源文件移动到系统回收站。

复制失败或系统回收站不可用时，源文件不会被直接删除。

### Link

素材库目录中创建指向源文件的链接，数据库保存源文件绝对路径。链接模式不会复制或移动源文件；源文件被删除或移动后，素材库链接会失效。

Windows 下优先创建符号链接；当前用户没有符号链接权限时，在同一磁盘自动回退为硬链接。跨磁盘无法创建硬链接时，需要开启 Windows 开发者模式或以管理员身份运行。

macOS 使用文件符号链接，通常不需要额外权限。Linux 使用符号链接。

## Electron 手动导入

Electron 客户端会通过 preload 的 `webUtils.getPathForFile()` 获取源文件绝对路径，并将其作为 `sourcePath` 发送到服务端。这样 `move` 模式才能操作用户选择的原始文件，而不是上传产生的临时文件。

## 浏览器和远程客户端导入

浏览器扩展等远程客户端无法向服务端提供可访问的源文件绝对路径，只能上传文件内容。因此这类请求始终按 `copy` 模式导入，并在导入成功后清理服务端上传临时文件，避免 `link` 指向临时文件或 `move` 将临时文件移入系统回收站。

## 路径字段说明

- `copy` / `move`：`files.path` 不保存源文件绝对路径；客户端通过素材库内的实际文件位置读取文件。
- `link`：`files.path` 保存源文件绝对路径；接口同时返回 `file_path`，用于读取素材库目录中的链接文件。
- 客户端预览优先使用 `file_path`，避免把数据库中的源路径误当作素材库文件路径。

## 常见问题

### Windows 链接创建失败 `EPERM`

开启“设置 → 系统 → 开发者选项 → 开发者模式”，然后完全重启 Mira。源文件和素材库在同一磁盘时，程序也会自动尝试硬链接。

### Link 导入出现重复条目

素材库自动同步 watcher 会忽略由上传接口刚创建的链接或副本。升级到包含 watcher 修复的版本后重新导入即可；升级前已产生的重复记录需要手动删除。

### Link 文件失效

检查 `files.path` 指向的源文件是否仍然存在。源文件被移动后，需要重新导入或改用 `copy` 模式。
