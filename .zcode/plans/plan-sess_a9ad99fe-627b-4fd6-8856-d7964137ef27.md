# 实现方案：将 SDK 能力暴露给 mira-app-server CLI，支持登录/凭证切换

## 概述

重构 `packages/mira-app-server/src/cli.ts`，使其成为完整的多功能 CLI，通过 `mira-app-core/shared/sdk` 的 `MiraClient` 调用远端服务器。核心是：

1. **凭证存储**：多 profile 模型，保存到 `~/.mira/credentials.json`
2. **登录命令**：`login` 后凭证持久化，后续命令自动复用，支持切换不同 profile
3. **全模块覆盖**：把 11 个 SDK 模块（auth/user/libraries/plugins/files/database/devices/system/tags/folders）的主要操作映射为子命令

## 关键设计

### 1. 凭证存储（新文件 `src/cli/credentials.ts`）

存储路径：`~/.mira/credentials.json`，结构：

```ts
interface CredentialProfile {
  server: string;       // e.g. http://localhost:8081
  token: string;        // accessToken
  username?: string;    // 登录用户名（便于辨识）
  updatedAt?: string;   // ISO 时间
}
interface CredentialsFile {
  current?: string;                       // 当前激活的 profile 名
  profiles: Record<string, CredentialProfile>;
}
```

提供函数：
- `loadCredentials()` / `saveCredentials(data)` —— 读写文件，目录不存在时自动创建（`fs.mkdirSync({recursive:true})`，权限 0o700）
- `getCurrentProfile()` —— 返回 `{name, profile}` 或 `null`
- `getProfile(name)` / `saveProfile(name, profile)` / `setCurrent(name)` / `removeProfile(name)` / `listProfiles()`
- 文件读写容错：损坏或缺失时回退为空结构，不崩溃

### 2. 客户端工厂（新文件 `src/cli/client.ts`）

```ts
// 解析 server: 优先 --server 参数，其次当前 profile，最后 DEFAULT_SERVER
function resolveServer(serverFlag?: string): string

// 从 profile 或 token 构建 MiraClient
function getClient(options?: { server?: string; token?: string }): MiraClient
```

- 默认 `DEFAULT_SERVER = 'http://localhost:8081'`
- 未登录时调用需鉴权的命令给出清晰提示：`❌ 未登录，请先运行: mira-app-server login`

### 3. CLI 命令结构（重构 `src/cli.ts`）

保留现有 `start` / `version` / `health`。新增命令（全部带 `--server` / `--profile` / `--token` 全局覆盖选项）：

**认证与凭证**
- `login [server]` —— 交互式输入用户名/密码（用 `readline`），登录成功后存为 profile。选项：`-u/--username`、`-p/--password`、`-s/--server`（默认 localhost:8081）、`--profile <name>`（默认 `default`）。登录后立即 `verify` 拉取用户信息并展示。
- `logout` —— 清除当前 profile 的 token
- `whoami` —— 显示当前登录用户（调 `client.user().getInfo()`）
- `auth use <name>` —— 切换当前 profile
- `auth list` —— 列出所有 profile 及当前激活项
- `auth add` —— 手动添加一个 profile（输入 server + token）
- `auth remove <name>` —— 删除 profile

**user**
- `user info` / `user update [--real-name] [--avatar]`

**libraries**
- `libraries list [--status active|inactive|error]`
- `libraries get <id>`
- `libraries create -n <name> -p <path> [--desc] [--icon] [--plugins-dir] [--no-hash]`
- `libraries update <id> [--name] [--desc] [--no-hash]`
- `libraries delete <id>`
- `libraries start <id>` / `libraries stop <id>` / `libraries restart <id>`

**files**
- `files list <libraryId> [--title] [--ext] [--tag] [--folder-id] [--limit] [--offset]`
- `files get <libraryId> <fileId>`
- `files upload <libraryId> <filePath...> [--tag] [--folder-id]` —— 用 Node `fs` 读文件构造 Blob/Buffer 上传
- `files download <libraryId> <fileId> [-o output]`
- `files rename <libraryId> <fileId> <name>`
- `files update <libraryId> <fileId> <json>`
- `files delete <libraryId> <fileId> [--permanent]`（默认进回收站，`--permanent` 移动到回收站=false 行为见下注）
- `files restore <libraryId> <fileId>`
- `files empty-trash <libraryId>`

> 注：SDK `delete` 的 `moveToRecycleBin` 默认 true。`--permanent` 映射为 `moveToRecycleBin=false`（彻底删除）。

**tags**
- `tags list <libraryId>`
- `tags create <libraryId> <title> [--parent-id] [--color] [--desc]`
- `tags update <libraryId> <id> [--title] [--parent-id] [--color] [--desc]`

- `tags file-set <libraryId> <fileId> <tag...>`

**folders**

- `folders update <libraryId> <id> [--title] [--parent-id] [--color] [--desc]`
- `folders delete <libraryId> <id> [--delete-files]`
- `folders move <libraryId> <fileId> <folderId>` / `folders remove <libraryId> <fileId>`

**plugins**

- `plugins install <name> <libraryId> [--version]`

**devices**

**database**

**system**
- `system health` / `system info`（替换原 health 命令的轻量版，保留独立 `health` 命令做向后兼容）

### 4. 全局选项与输出约定

- 通过 `program.option()` 暴露全局 `--server`、`--token`、`--profile`、`--json`（原始 JSON 输出，便于 agent 解析）。命令 action 内通过 `program.opts()` 读取。
- 默认人类可读输出（表格/键值对），`--json` 时直接 `console.log(JSON.stringify(data, null, 2))`。
- 错误统一处理：action 内 try/catch，失败打印 `❌` + message 后 `process.exit(1)`。

### 5. Node 环境适配

- SDK 的 `FileModule.upload` 用了浏览器 `FormData`/`File`。Node 18+ 已内置全局 `FormData`、`File`、`Blob`，tsconfig target ES2020 + `@types/node@^20` 可直接用。上传时用 `new Blob([fs.readFileSync(path)])` 构造，文件名从路径取。
- `download` 返回 Blob，CLI 中转成 Buffer 写入目标文件。
- 交互输入用 Node 内置 `readline/promises`（无需新依赖）。

## 文件改动清单

| 文件 | 操作 |
|---|---|
| `packages/mira-app-server/src/cli.ts` | 重构：精简为入口，保留 start/version/health，注册全局选项 |
| `packages/mira-app-server/src/cli/credentials.ts` | **新建**：profile 存储与切换 |
| `packages/mira-app-server/src/cli/client.ts` | **新建**：server 解析 + MiraClient 工厂 + 登录辅助 |
| `packages/mira-app-server/src/cli/commands/*.ts` | **新建**：按模块拆分命令注册（auth, user, libraries, files, tags, folders, plugins, devices, database, system），每个文件导出 `register(clientFactory)` |
| `packages/mira-app-server/src/cli/format.ts` | **新建**：输出格式化（JSON / 表格）小工具 |

不改动 SDK 与 server 业务代码；只新增 CLI 侧文件 + 改写 cli.ts。`package.json` 无需新增依赖（commander/readline/fs/axios 均已有或为 Node 内置）。

## 验证方式

1. `pnpm --filter mira-app-server build` 通过 tsc 编译，无类型错误。
2. 手动跑 `node dist/cli.js --help`、`... login --help`、`... auth list`（未登录时给出清晰提示）验证命令注册与凭证文件读写。
3. 对运行中的本地服务器走通：`login` → `whoami` → `libraries list` → `files list <id>` → `logout`。
