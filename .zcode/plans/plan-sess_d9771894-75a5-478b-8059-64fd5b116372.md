## 目标
让 `pnpm dev:client-plugins` 一条命令同时：① 监听 `online_client_plugins/plugins/` 自动重建 `plugins.json`；② 在 8080 端口（带 CORS）提供静态服务，客户端可直接拉取 `plugins.json` 与各插件文件。

## 根因
`scripts/build-client-plugins-index.mjs` 只负责"生成/重建索引"，从未启动 HTTP 服务；README 把"提供静态服务"作为**独立**步骤单列（`npx serve ... -p 8080`）。所以只跑 `dev:client-plugins` 不会开 8080，符合现状、但不符合直觉。

## 改动方案（合并到一条命令，零运行时依赖）

### 1. `scripts/build-client-plugins-index.mjs`
- **新增 `--serve` 模式**：用 Node 内置 `http` + `fs/promises`（与脚本现有零依赖原则一致，不引 `serve`/`express`）起一个静态服务，root = `ROOT`（即 `online_client_plugins/`）。
- 行为：
  - URL 路径映射到 `ROOT` 下文件；`/` → `index.html`（若存在）或目录列表/`plugins.json`。
  - **始终带 CORS 头**：`Access-Control-Allow-Origin: *`（客户端跨域拉取必需，README 方式二 nginx 也强调过）。
  - 常见 MIME 类型映射：`.json` → `application/json; charset=utf-8`、`.js` → `text/javascript`、`.md` → `text/markdown`、`.html` → `text/html`、其余按扩展名映射，未知类型回退 `application/octet-stream`。
  - 404 时返回 JSON 错误信息，便于客户端识别。
  - 端口来源（优先级）：CLI `--port <n>` > `process.env.PORT` > 默认 **8080**。
  - 启动后打印一行清晰提示，例如：
    `🌐 静态服务已启动: http://localhost:8080 （市场源根目录；客户端「插件市场源」填该地址）`
- **`--watch --serve` 组合**：watch 逻辑保持不变（300ms 防抖重建索引）；serve 在 watch 初始化成功后启动，二者并行运行在同一进程。
- **保持向后兼容**：
  - 不带任何 flag（`build:client-plugins-index`）→ 仅生成一次索引，行为完全不变。
  - 仅 `--watch` → 仅 watch 重建，行为不变（不走 HTTP）。
  - 新增 `--serve`（可单独用：起服务但只生成一次索引、不监听）。

### 2. `package.json`
- `dev:client-plugins`: `node scripts/build-client-plugins-index.mjs --watch` → `node scripts/build-client-plugins-index.mjs --watch --serve`
- `build:client-plugins-index` 保持不变。

### 3. `online_client_plugins/README.md`
- 在「索引脚本（自动更新）」一节明确：现在 `pnpm dev:client-plugins` 会同时 watch 重建索引 **并** 在 8080 起静态服务（带 CORS）；端口可用 `PORT=9000` 或 `--port 9000` 覆盖。
- 「如何对外提供静态服务 → 方式一」更新为：本地调试现在直接 `pnpm dev:client-plugins` 即可，无需再额外 `npx serve`。

## 不做
- 不引入任何 npm 依赖（遵循脚本既有零依赖设计）。
- 不改动 `build:client-plugins-index` 单次生成逻辑与输出格式。
- 不改 `plugins.json` schema / 内容。
- 不动 `packages/mira-app-server` 的 8081（那是另一套服务）。

## 验收
1. `pnpm dev:client-plugins`：日志同时出现 watch 启动 + `🌐 静态服务已启动: http://localhost:8080`。
2. `curl http://localhost:8080/plugins.json` 返回 JSON，响应头含 `Access-Control-Allow-Origin: *` 和正确 MIME。
3. 改一个插件文件 → 300ms 内日志显示重建 `plugins.json`，且 `curl .../plugins.json` 看到新 `generatedAt`。
4. `PORT=9000 pnpm dev:client-plugins` 在 9000 起服务；`--port` 同理。
5. `pnpm build:client-plugins-index`（无 flag）仍仅生成一次索引、不监听、不起服务。
