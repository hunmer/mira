# Eagle 插件重构：全局单例 + 库选择器配置页

## 问题
`ServerPluginManager` 是 **per-library** 的（`LibraryStorage.ts:50-54` 每个库 `new` 一个），所以 `init(inst)` 被调用 N 次，每次都 `listen(41595/41593)` → 第 2 个库 `EADDRINUSE`。

## 解决方案：模块级单例 + 请求时解析目标库 + 配置页

### 1. 全局单例（端口只 bind 一次）
利用 Node `require` 缓存：`ServerPluginManager.loadPlugin` 只在 `reload=true` 时清 `require.cache`（`:114-118`），正常加载共享同一模块实例。

`index.ts` 顶部：
```ts
let globalServer: MiraEagleExtension | null = null;
export function init(inst) {
  if (globalServer) return globalServer;   // 已存在，直接返回，不再 listen
  globalServer = new MiraEagleExtension(inst);
  return globalServer;
}
```
构造函数里 `start()` 只在首次创建时执行（天然如此，因为单例只 new 一次）。

### 2. 请求时解析目标库的 dbService（不再绑定 init 时的库）
所有路由处理器把 `this.dbService` / `this.libraryId` 替换为运行时解析：
```ts
getTargetDbService() {
  const backend = this.pluginManager.server.backend;
  const obj = backend.libraries.getLibrary(this.config.targetLibraryId);
  if (!obj?.libraryService) return null;   // 库未启用/不存在
  return obj.libraryService;                // === dbService
}
```
（`LibraryStorage.ts:118-120` + `:9-15` shape，`mira_n8n/index.ts:109` 同款用法）

入库时广播也用 `this.config.targetLibraryId`。

### 3. 非库级配置端点（供配置页读写）
库级 `httpRouter.registerRounter` 强制要求每个请求带 `libraryId`（`HttpRouter.ts:28-32`），不适合全局配置页。改用 `MiraHttpServer.app` 直接挂（`HttpServer.ts:134` 公开，`/api` 前缀仍走 token 中间件 `:231-235`，保持鉴权）：
```ts
const app = backend.getHttpServer().app;
app.get('/api/eagle/config',  this.handleGetConfig);   // 返回 { targetLibraryId, ports, status, libraries }
app.post('/api/eagle/config', this.handleSetConfig);   // 写 data/config.json
```
**用 `app._eagleConfigRegistered` 标志位守卫，只注册一次**（因为 `init` 可能被调多次）。

### 4. 配置页组件（仿 `DuplicateScanner.js`）
新建 `components/EagleConfig.js`：IIFE 注册到 `window.MiraPluginComponents['mira_eagle_extension_components_EagleConfig_js']`（key = `${pluginName}_${'components/EagleConfig.js'.replace(/[/.]/g,'_')}`，匹配 `pluginRoutes.ts:74`）。结构：
- `mounted()`：`Dashboard.getLibraries()`（`stores/app.ts:33-42` → `GET /api/libraries`，返回 `{id,name}[]`）+ `GET /api/eagle/config` 取当前配置
- 库选择器 `<MiraSelect v-model="targetLibraryId">`（同 DuplicateScanner `:40-49`）
- 保存按钮 → `POST /api/eagle/config { targetLibraryId }`（`authHeaders()` 带 token）
- 展示：当前端口、服务状态、目标库

### 5. 注册 dashboard 路由（让 `/tools/eagle-extension` 可访问）
构造函数 `this.routes.push`（`getRoutes()` 被 `ServerPluginManager.getAllPluginRoutes` 消费 → `pluginRoutes.ts` 注入 `MainLayout` 子路由）：
```ts
this.routes.push({
  name: 'EagleConfig',
  group: '工具',
  path: '/tools/eagle-extension',
  component: 'components/EagleConfig.js',
  pluginName: this.pluginName,
  meta: { title: 'Eagle 扩展', roles: ['super','admin','user'] },
});
```
URL = `http://127.0.0.1:5173/#/tools/eagle-extension`（5173 = dashboard dev 端口 `SettingsManager.ts:13`，hash 路由 `router/index.ts:17`）。

### 6. 配置持久化
`PluginConfig` 增加 `targetLibraryId: string`，`loadConfig` 合并默认值（沿用现有 `data/config.json` 读写逻辑 `index.ts:66-98`）。新增 `saveConfig()` 写回 `data/config.json`（仿 `mira_thumb_imagemagick/index.ts:109-111`）。

## 关键实现细节
- **单例守卫**：`init` 里 `if (globalServer) return globalServer`；`app` 路由注册用 `if (app._eagleConfigRegistered) ... ` 避免重复。
- **目标库为空时**：Eagle 请求进来自动返回 `{ status:'failed', code:'no target library' }`，提示用户去配置页选库。
- **目标库被禁用时**：`getTargetDbService()` 返回 null → 同上处理。
- **组件文件服务**：`components/EagleConfig.js` 经 `HttpRouter.ts:148-235` 从 `getPluginDistDir` 回退 `getPluginDir` 提供，无需编译（JS 直接 eval，`pluginRoutes.ts:79-83`）。
- **鉴权**：`/api/eagle/config` 在 `/api` 下，自动走 token 中间件；前端 `authHeaders()` 带 Bearer token。
- **实时刷新**：入库后 `broadcastLibraryEvent(targetLibraryId, 'file::created', file)`。
