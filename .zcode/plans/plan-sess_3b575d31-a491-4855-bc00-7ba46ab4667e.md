# Eagle 浏览器扩展支持 — 服务端插件实现计划

## 关键说明：保存位置
你最初要求保存到 `packages\mira-client\plugins`。但那是 **客户端插件目录**（注入到渲染进程、受 `contextIsolation` 限制、无法监听端口）。你已确认要做成 **服务端插件**，而服务端插件由 `mira-app-server` 的 `ServerPluginManager` 加载（`require()` 完整 Node 环境），其扫描目录由库配置 `dbConfig.pluginsDir` 指定。

本仓库实际在用的、已被 `mira_duplicate_scanner` 验证可用的服务端插件目录是：

**`D:\mira_typescript\plugins\plugins\mira_eagle_extension\`** ← 插件将创建在此处

并在 `D:\mira_typescript\plugins\plugins\plugins.json` 追加一条启用记录。这样插件才会真正被加载、端口才会真正监听。放在 `packages\mira-client\plugins` 下将无法运行（会被当作客户端插件注入渲染进程，且不是服务端插件的扫描目录）。

## 功能对齐（源 `server.js` → 本插件）

源 `server.js` 做三件事，本插件逐一对齐，但"下游目标"从 Eagle 的 `127.0.0.1:41597` 改为 **直接操作 Mira 当前库的 `dbService`**：

| 源 server.js 行为 | 本插件对应实现 |
|---|---|
| `GET /` 返回 `getInfomation()`（伪装 Eagle，含 `preferences.developer.apiToken`） | 同样在 **41595 和 41593** 两个端口各起一个原生 `http` 服务，`GET /` 返回等价的 Eagle 信息 JSON（含 `apiToken`，从插件配置读取，默认沿用源文件的 token 占位） |
| `POST :41595/api/folder/create` → 转发 41597 | 直接调用 `dbService.createFolder({ title, parent_id, color, icon, sort_index })`，返回 `{ id }` |
| `POST :41595/api/item/addFromURLs`（body: `{folderId, items:[{name,url,website,modificationTime}]}`）→ 转发 `addFromPaths` | 对每个 item：把 `url` 作为远端图床地址，用 `reference`/`path` 字段存 URL（Mira 支持 `isUrlFile` 的 URL 文件，无需下载即可缩略/访问），调 `dbService.createFile({...})`；通过 `setFileFolder` 归入 `folderId`；`meta.url/tags` 写入 `custom_fields` |
| `GET :41595/api/folder/listRecent` → 转发 41597 | 用 `dbService.getAllFolders()` 取回，按最近有文件导入的时间排序，返回前 N 条（Eagle 协议格式） |
| `POST :41593/`（type 为 image/screen capture/save-url，body 含 `src/url/base64/...`） | 把图片（base64 优先，否则 `src` URL）下载到临时文件，调 `createFileFromPath(tempPath, {...}, {importType:'move'})` 落盘入库；`folderID` 归类；`metaTags/metaDescription/url` 写入 `custom_fields`；完成后 `broadcastLibraryEvent(libraryId, 'file::created', file)` 让前端实时刷新 |
| `GET :41593/exit` | `process.exit(0)`（保持原行为） |
| CORS 头（`Access-Control-Allow-Origin: *` 等） | 所有响应统一加，保证浏览器扩展跨域可用 |

> 与源文件的唯一行为差异：源是"转发给本机 Eagle"；本插件是"直接写入 Mira 当前库"。这是"相同功能"在 Mira 语义下的等价落地——Eagle 扩展保存的图片会真正进入 Mira 素材库并在前端实时显示。

## 文件清单

创建目录 `D:\mira_typescript\plugins\plugins\mira_eagle_extension\`，包含：

1. **`index.ts`** — 插件主入口
   - `class MiraEagleExtension`（不继承任何基类，符合服务端插件规范）
   - `constructor(inst)`：从 `inst` 取 `pluginManager`、`dbService`；解析 `libraryId = dbService.getLibraryId()`；读配置；启动两个 `http.createServer` 监听 41595 / 41593
   - `getInformation()`：返回 Eagle 风格信息对象
   - 各路由处理函数（如上表），全部自带 CORS 头 + JSON 响应

## 技术要点（已核实）

- **注册方式**：服务端插件由 `ServerPluginManager` 在 `loadPlugin` 中 `require()`（`ServerPluginManager.ts:118-126`），调用 `pluginModule.init({pluginManager, server, dbService, miraClient})`。无沙箱，可自由 `require('http'/'fs'/'path')`。
- **监听端口**：直接用 Node 内置 `http.createServer(...).listen(port)`（参照 `mira_n8n` 用 `ws.WebSocketServer({port})` 的先例），不依赖 express/request（避免额外依赖）。
- **dbService 真实方法**（已核实签名）：
  - `getLibraryId(): string`
  - `createFolder(folderData): Promise<number>`（返回新 folder id）
  - `getAllFolders(): Promise<Record[]>`
  - `createFile(fileData): Promise<Record>`（字段：name/created_at/imported_at/size/hash/custom_fields/notes/stars/folder_id/reference/path/thumb/recycled/tags/uploader）
  - `createFileFromPath(filePath, fileMeta, {importType}): Promise<Record>`（用于 base64/下载后的文件落盘，自带去重）
  - `setFileFolder(fileId, folderId): Promise<{success,oldData}>`
- **实时刷新**：导入后调 `pluginManager.server.backend.getWebSocketServer().broadcastLibraryEvent(libraryId, 'file::created', file)`（前端监听该事件刷新网格）。
- **配置持久化**：`pluginManager.getPluginDir(name)` 定位插件数据目录，读写 `data/config.json`。
- **CORS**：所有响应头加 `Access-Control-Allow-Origin: *` 与 `Access-Control-Allow-Headers`，复刻源 `echoJson`。

## 与源 server.js 的差异（诚实声明）

1. **下游目标**：源转发到 Eagle（`127.0.0.1:41597`）；本插件直接写入 Mira 当前库（这是用户期望的"在 Mira 里复刻 Eagle 扩展保存功能"）。
2. **依赖**：源用 `express` + `body-parser` + `request`；本插件用 Node 内置 `http` + `fetch`/`http.get`，零第三方运行时依赖。
3. **端口与协议**：41595 / 41593 端口号、路径、`GET /` 返回的 Eagle 信息结构、Eagle 扩展 POST :41593 的 type 判定（`image/screen capture/save-url`）均与源一致，保证 Eagle 浏览器扩展无需改动即可对接。
