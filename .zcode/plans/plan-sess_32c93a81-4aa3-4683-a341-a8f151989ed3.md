## 目标
给本地插件列表增加「检查更新」功能：对比本地已安装插件与市场条目，判断条件为 **版本更低** 或 **文件 sha256 列表对不上** 即标记为可更新。

## 数据流
市场条目已携带 `version` + `files: [{path, size, checksum}]`（sha256）。本地插件只有 `config` + `directory`，无文件哈希。需新增主进程 IPC 计算本地插件文件 sha256，再由 store 协调对比。

## 改动清单

### 1. 主进程：新增文件校验和 IPC — `PluginHandler.ts`
- 新增 `plugin:compute-file-checksums` handler：入参 `pluginId`，在 `pluginsDirectory/<pluginId>/` 下递归收集文件（复用 `IGNORED_NAMES` 过滤逻辑），对每个文件计算 sha256，返回 `{path, size, checksum}[]`（结构同 `MarketplacePluginFile`，posix 相对路径）。
- 目录不存在时返回空数组。

### 2. Preload 暴露 — `preload.ts`
- `plugin` 命名空间下新增 `computeFileChecksums: (pluginId) => ipcRenderer.invoke('plugin:compute-file-checksums', pluginId)`。

### 3. PluginService 转发 — `PluginService.ts`
- 新增 `getLocalFileChecksums(pluginId)`：Electron 环境调用 `electronAPI.plugin.computeFileChecksums`，返回 `{success, data}`；非 Electron 返回空。

### 4. Store：检查更新逻辑 — `plugin.ts`
- 新增状态 `pluginUpdates: ref<Map<pluginId, {version?: string, fileMismatch: boolean}>>`（待更新插件的缓存）+ `isCheckingUpdates: ref(false)`。
- 新增 `checkPluginUpdates()`：
  1. 确保市场目录已加载（无市场源则直接返回空）。
  2. 对每个本地插件，在市场条目中找同 `pluginId`：
     - 版本对比：市场 version > 本地 → 标记。
     - 文件对比：调 `getLocalFileChecksums(pluginId)` 得本地文件列表，与市场 `entry.files` 按 path→checksum 比对（数量不同或有 path 的 checksum 不一致 → 标记 `fileMismatch`）。**仅当市场条目含 files 清单时才做文件比对**（兜底：无 files 则只看版本）。
  3. 结果写入 `pluginUpdates`。
- 导出 `pluginUpdates`、`isCheckingUpdates`、`checkPluginUpdates`。

### 5. UI：PluginsDialog.vue
- 本地插件卡片：若 `pluginUpdates.has(pluginId)`，显示「可更新」徽章（点击直接走 `installMarketplacePlugin(entry)` 更新）。
- 顶部操作栏新增「检查更新」按钮（refresh 图标旁），点击调 `pluginStore.checkPluginUpdates()`，进行中显示 loading。
- 切换到本地 tab 且有市场源时自动触发一次检查（复用 `watch(activeTab)`）。

## 不变项
- 市场索引结构、安装/下载流程不变。
- `getMarketStatus`（市场 tab 的状态判断）保持原样。

## 验证
- 修改本地插件某文件（不改版本）→ 检查更新应标记 fileMismatch。
- 本地版本落后 → 标记可更新。
- 版本与文件均一致 → 不标记。
- 无市场源 → 检查更新静默返回空。
