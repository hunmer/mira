## 迁移目标
把 Eagle 插件 `8f788ab3...`（zipper：zip/rar/7z/tar 归档浏览器）迁移为 Mira 服务端格式插件 **`mira_zipper_format`**。按确认的范围：**只读浏览预览** + **ZIP 走 yauzl，rar/7z/tar 暂不支持** + **viewer 重写为原生 HTML/JS**。

## 设计要点

### 服务端：`plugins/plugins/mira_zipper_format/index.ts`
- `init(inst)` → `new MiraZipperFormatPlugin(inst)`，构造里 `inst.pluginManager.registerFileFormat('mira_zipper_format', handler)`。
- 缓存目录 `path.join(inst.server.backend.dataPath, 'temp', 'zipper')`，按源文件绝对路径 sha256 + `size:mtimeMs` 指纹缓存解压结果（`pending` Map 合并并发），manifest 成功后才落盘，失败递归清理。
- 用 **`yauzl` lazy entries 流式解压**（参照 `mira_livp_format/livpBundle.ts` 的安全骨架）：拒绝绝对路径/`..`/NUL；限制条目数（如 5000）、单条目大小（64MB）、总大小（1GB）；目标路径 `path.resolve` 并校验位于缓存根内。
- `extensions: ['zip']`（仅 zip），`mimeTypes: ['application/zip', 'application/x-zip-compressed']`，`thumbnailExtensions: ['zip']`。
- `process(filePath, context)`：返回 `{ format:'zip', size, entryCount, topDirs, ...context }`（轻量元信息，不全量回传条目）。
- 缓存产物：把解压结果放在 `temp/zipper/<key>/`（保留相对目录结构），并写 `manifest.json`（指纹 + 条目索引 `entries.json`：`[{name, size, compressedSize, isDir}, ...]`）。
- `getExtraFileList(filePath)`：返回 `['index.json', '<entryPath>', ...]`——其中 **`index.json` 是固定聚合文件**，内容为条目清单（含 name/size/compressedSize/isDir/previewType），viewer 一次拉到完整目录树；其余为归档内原条目路径（按需懒加载）。
- `getExtraFile(filePath, fileName)`：
  - `fileName === 'index.json'` → 返回 manifest 旁的 `index.json`。
  - 否则 `fileName` 必须命中已解压条目（白名单），`path.resolve` 后校验位于缓存根内，返回真实路径。
- `thumbnail(srcPath, destPath)`：找归档内**第一个图片条目**（jpg/jpeg/png/gif/webp/bmp），用 `sharp` 缩到 ≤512（`fit:inside, withoutEnlargement`）转 PNG；无图片条目则画一个通用"归档"SVG 占位（参照 epub 的 fallbackCover 模式）。自行 `mkdir(path.dirname(destPath))`。
- `viewers: [{ viewerId:'mira-zipper', title:'归档浏览', icon:'folder_zip', entry:'viewer.html', priority:10, getQuery(ctx) => ({ indexUrl: ctx.getExtraFileUrl('index.json'), fileName: ctx.file.name, fileId: ctx.fileId }) }]`。
- rar/7z/tar：**不注册扩展名**（不会被 Mira 识别为该插件可处理），无需显式"不支持"分支——SKILL 要求的最小可用边界。

### Viewer：`plugins/plugins/mira_zipper_format/web/viewer.html`（纯原生 HTML/JS）
- 无 React/Vue/i18next，无 `require`，无 `eagle.*`。单文件 `<script>`。
- 读 query：`indexUrl`（带 token，fetch 拿 `index.json`）、`fileName`、`fileId`。
- 左侧：归档目录树/列表（按 `/` 分层），显示 name + size + 压缩后大小；右侧：选中条目的预览。
- 图片条目：`<img src="<base>/api/files/extra/<lib>/<file>/<entryPath>?token=...">`。但 viewer 在 iframe 里拿不到 libraryId/fileId/token；**统一通过 `indexUrl` 推导 base + token**：从 `indexUrl` 解析出 `extra` 前缀和 `token` query，条目 URL = `<prefix>/api/files/extra/<lib>/<file>/<encodedEntry>?token=<token>`。fallback：若 URL 推导失败仅显示文件名/大小。
- 文本类条目（txt/md/json/log/csv/xml/html/css/js 等，按扩展名白名单 + 大小上限如 256KB）：fetch 后 `<pre>` 显示。
- 视频/音频条目：`<video controls>`/`<audio controls>` 用同款 URL（mp4/webm/mov/mp3/wav/ogg 白名单）。
- 其他类型：仅显示文件名 + 大小 + "不支持预览"。
- 启动参数缺失/`index.json` 拉取失败：显示明确错误，`parent.postMessage({type:'mira-zipper-preview-error', fileId})` 通知宿主（供 hovercard 降级，按需）。

### 客户端注册：`plugins/plugins/mira_zipper_format/web/index.js` + `web/plugin.json`（IIFE）
- `PLUGIN_ID` 与 `plugin.json` 的 `pluginId` 一致（生成新 UUID，不复用 Eagle 的 `8f788ab3...`，以免与源插件冲突）。
- `api.media.registerFileFormat({ id:'mira-zipper', title:'归档浏览', icon:'folder_zip', extensions:['zip'], mimeTypes:['application/zip','application/x-zip-compressed'], openByDefault:true, getPreviewUrl(file) → viewer.html?... })`：
  - `getPreviewUrl` 内 `api.media.getExtraFileList(libraryId, fileId)` 确认含 `index.json`，再用 `api.media.getExtraFileUrl(libraryId, fileId, 'index.json')` 拼 viewer URL（附 `fileName`/`fileId`，不带 `embed`）。
- 标准 `setup()` 轮询 `window.pluginSystem.registerPluginInstance`。

### 清单 / 依赖 / 构建（三处登记）
1. `plugins/plugins/plugins.json`：追加 `{ "name":"mira_zipper_format", "enabled":true, "path":"mira_zipper_format" }`（保留其余条目）。
2. `packages/mira-app-server/src/plugins/package.json`：加 `"mira_zipper_format": "file:../../../../plugins/plugins/mira_zipper_format"`。
3. `packages/mira-app-server/src/plugins/plugins.json`：加 `{ "name":"mira_zipper_format", "enabled":true, "path":"node_modules/mira_zipper_format" }`（保留其余用户改动）。

### 插件自身 package.json / tsconfig
- 仿 `mira_epub_format`：`main: dist/index.js`，`files: [dist/**, web/**, package.json, README.md]`，`scripts.build: tsc`，`deps: yauzl ^3.3.0, sharp ^0.35.3`，`devDeps: @types/node, @types/yauzl, typescript`。tsconfig 同模板。

### 测试：`test.js`（最小行为检查，仿 epub）
- 内置 ZIP 构造器（直接复用 epub test.js 的 `makeZip`/crc32）。
- 造一个含 `cover.png` + `notes.txt` + `data/sub.txt` 的 zip，`init({pluginManager:{registerFileFormat:(n,h)=>{handler=h;return ()=>{}}}})`。
- 断言：`process` 返回 `format:'zip'`；`getExtraFileList` 含 `index.json`；`getExtraFile(fz,'index.json')` 存在；`getExtraFile(fz,'notes.txt')` 存在；`thumbnail` 生成 png 且尺寸 ≤512。
- `test-browser-bundle.js`：静态扫 `web/index.js`、`web/viewer.html` 无 `require(`、`module.exports`、`eagle.`、`i18next`（回归检查）。

## 执行步骤
1. 创建上述插件目录与文件。
2. 在插件目录 `npm install` → `npm run build` → `npm test`。
3. `cd packages/mira-app-server/src/plugins && npm install`（让 `node_modules/mira_zipper_format` Junction 生成，更新 lockfile）。
4. 用 procm-mcp 重启已有 Mira 服务（无运行中的服务不擅自启动）。
5. 查日志确认 `[mira_zipper_format]` 注册行 + ThumbnailService 注册 `zip` 扩展名 + 无 `Failed to load plugin`。
6. `npx ts-node packages/mira-app-server/src/cli.ts --json system health` 应返回 `status:ok`。

## 验收标准
- `npm test` 全绿。
- 服务重启后日志含插件注册与 `zip` 缩略图扩展名。
- `system health` 返回 ok。
- 导入真实 .zip：缩略图生成；viewer 内左侧目录树、图片/文本/视频内联预览、不支持类型显示提示。
- rar/7z/tar 不被本插件接管（保持原行为，不报错）。
