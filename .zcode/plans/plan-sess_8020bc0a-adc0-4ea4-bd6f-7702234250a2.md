# PluginsDialog 按功能拆分方案

## 目标
将 1331 行的 PluginsDialog.vue 按功能拆成「主组件(壳) + 5 个子组件 + 2 个 colocated composable」，**功能与外观完全不变**。

## 目录结构（遵循仓库 FileUploadDialog/MediaGridComponent 惯例）
```
packages/mira-client/src/renderer/components/business/
├── PluginsDialog.vue                    ← 主组件(壳)，负责 Dialog 包裹 + tab路由 + 初始化watch，~120行
└── PluginsDialog/
    ├── PluginToolbar.vue                ← 第一行右侧：搜索框 + 刷新/检查更新/添加 三个操作按钮
    ├── PluginCategoryBar.vue            ← 第二行：类别横向滚动按钮栏(带LayoutGroup滑动动画)
    ├── PluginCard.vue                   ← 统一卡片：props={kind:'local'|'server'|'market', data}，内部 v-if 区分操作按钮
    ├── PluginMarketGrid.vue             ← online tab 列表(含安装进度条/取消/市场源切换/空状态) — 因市场逻辑最复杂单独拆
    ├── PluginDetailPanel.vue            ← 右侧详情栏(选中后展开的全部详情内容)
    └── composables/
        ├── usePluginTabs.ts             ← activeTab/pluginTabs 配置 + tab切换副作用watch(清选中/按需加载市场/检查更新)
        └── usePluginSelection.ts        ← selectedKind/selectedPluginId/选中互斥逻辑 + 派生的 selectedRuntime/selectedMarket/detailTags
```

## 各文件职责与状态来源（直接用 store）

### PluginsDialog.vue（主壳，~120行）
- Dialog 包裹、DialogContent 固定 80vh + grid 布局
- 调用 `usePluginTabs()` 和 `usePluginSelection()` 获得响应式状态
- 模板：PluginToolbar → PluginCategoryBar → 主内容区(local/server 用 PluginCard 列表，online 用 PluginMarketGrid) → PluginDetailPanel
- 保留 isVisible watch(初始化刷新)、市场源变化 watch
- **categories 计算属性**移入 `usePluginTabs`(依赖 activeTab + store)

### PluginToolbar.vue
- props: 无（直接 usePluginStore + useSettingsStore）
- 内部：搜索框(InputGroup)、刷新按钮、检查更新按钮(仅 local+有市场源)、添加按钮
- searchQuery：本地 ref，通过事件或直接 emit 给父（或放 usePluginTabs）。**决定：searchQuery 放 usePluginTabs，子组件解构使用**
- 刷新/检查更新/添加：各自方法，直接调 store + toast

### PluginCategoryBar.vue
- props: 无（从 usePluginTabs 解构 categories + selectedCategory）
- 渲染类别按钮栏 + LayoutGroup 滑动动画

### PluginCard.vue（统一卡片，~150行）
- props: `kind: 'local'|'server'|'market'`, `plugin: PluginRuntime | MarketplacePluginEntry`
- 顶部布局统一：图标+名称+描述+badge/开关
- 底部操作区按 kind v-if 分支（local: 详情/重载/更新/卸载；server: 详情/服务器提供；market: 安装/更新/已安装 + 进度条）
- 选中态、点击选中逻辑：从 usePluginSelection 解构 selectPlugin/isSelected
- toggle/install/remove 等方法：直接调 store + toast

### PluginMarketGrid.vue（online 专用）
- 市场源切换 Select、加载中/失败/空状态、市场卡片网格
- 内部复用 PluginCard(kind='market') 或自带市场卡片渲染（**决定：网格容器负责空状态，单卡片仍用 PluginCard**）
- market 状态判断 getMarketStatus / 安装进度等方法：直接 usePluginStore + 本地 helper

### PluginDetailPanel.vue（右侧详情栏）
- props: 无（从 usePluginSelection 解构 selectedRuntime/selectedMarket/selectedKind/detailTags + clearSelection）
- 详情头部、描述、操作按钮(按 kind)、字段表、标签、平台、错误信息
- 安装进度条等：直接 usePluginStore

### composables/usePluginTabs.ts
导出工厂函数 `usePluginTabs()`，返回：
- `activeTab`(ref)、`pluginTabs`(配置数组)
- `categories`(computed，依赖 activeTab + pluginStore)
- `selectedCategory`(ref)
- `searchQuery`(ref)
- tab 切换副作用 watch（清选中、重置类别、按需加载市场/检查更新）

### composables/usePluginSelection.ts
导出工厂函数 `usePluginSelection()`，返回：
- `selectedKind`/`selectedPluginId`(ref)、`selectPlugin`/`clearSelection`/`isSelected`(方法)
- `selectedRuntime`/`selectedMarket`/`selectedDetail`/`detailTags`(computed)
- 选中状态在 usePluginTabs 切换 tab 时通过调用 clearSelection 联动

## 关键实现要点
1. **两个 composable 都是无状态工厂函数**（模式 B），每次调用返回新状态 —— 但因为 PluginsDialog 主组件只调用一次，状态在主组件内是单例的。子组件**不重复调用** usePluginSelection/usePluginTabs，而是由主组件调用后通过组合式 API 的依赖方式传递：实际上最简做法是**主组件调用一次，把返回值通过 provide/inject 提供给所有子组件**（避免逐层 props 透传）。

   → **改用 provide/inject**：主组件 `provide('pluginDialog', { activeTab, selectedCategory, searchQuery, ...selection })`，子组件 `inject('pluginDialog')` 解构。这是 Vue 中共享组件树内 UI 状态的惯用法，比 props 透传干净，比 store 更适合"仅此对话框内有效"的局部状态。

2. **可变状态总览**（provide 的对象内容）：
   - 来自 usePluginTabs：activeTab、pluginTabs、categories、selectedCategory、searchQuery
   - 来自 usePluginSelection：selectedKind、selectedPluginId、selectPlugin、clearSelection、isSelected、selectedRuntime、selectedMarket、selectedDetail、detailTags

3. **watch 副作用归位**：tab 切换 watch 放 usePluginTabs（依赖 pluginStore + libraryStore + clearSelection）；对话框打开 watch 放主组件。

4. **纯工具函数**（getMarketStatus / compareVersions / platformLabel / getInstallPercent / getInstallPhase / isInstalling / getPluginUpdate）放在 PluginCard/PluginMarketGrid/PluginDetailPanel 各自就近，或抽到 `PluginsDialog/utils.ts`。**决定：抽到 utils.ts 供多组件复用**（getMarketStatus/compareVersions/platformLabel 被卡片和详情栏共用）。

5. **i18n / toast / confirm**：各子组件按需自行 `useI18n()` / `useToast()` / `useConfirm()`，仓库惯例如此。
