## 实现计划：网络设置（HTTP 代理）+ 通用下载服务

### 设计决策（已与用户确认）
- **代理作用域**：全部网络请求。主进程启动时读取持久化的代理配置 → `setGlobalDispatcher(new ProxyAgent(url))`（覆盖 Node 全局 `fetch`，影响插件下载/自更新/npm 部署）+ `session.defaultSession.setProxy({proxyRules})`（影响渲染层 `fetch`，如 `fetchMarketplaceCatalog`）。
- **下载 API 形态**：主进程内部服务。新建 `DownloadService`，封装「带代理 + 进度 + 取消 + sha256 校验」的通用下载能力。`PluginHandler.downloadAndVerifyFile` 改为内部调用它。IPC 边界不变（插件下载仍走 `plugin:install-from-marketplace`），`PluginsDialog.vue` 无需改动下载调用路径。
- **零新依赖**：`undici` 随 Electron 内置的 Node 18+ 提供，`ProxyAgent` 已验证可用（`require('undici').ProxyAgent`）。

**文件**：`packages/mira-client/src/renderer/stores/settings.ts`
- 在 `AppSettings` 接口（L15–76）新增：
  ```ts
  // 网络设置
  networkProxyEnabled: boolean       // 是否启用代理
  networkProxyUrl: string            // 代理地址，如 http://127.0.0.1:7890
  ```
- 在 `settings` ref 默认值（L137–194）和 `resetSettings` 的 `defaultSettings`（L479–520）同步新增字段默认值（`false` / `''`）。
- 在 `updateSetting`（L420）追加分支：当 `networkProxyEnabled` 或 `networkProxyUrl` 变更时，调用新增 IPC `network:set-proxy` 把 `{ enabled, url }` 推到主进程即时生效。
- 在 `loadSettings`（L351）末尾追加：首次加载后把当前代理配置推给主进程（确保启动后的设置变更已落库、再次启动即由主进程自举读盘）。

### 第 2 步：新建主进程 `DownloadService`（核心下载 API）
**新文件**：`packages/mira-client/src/main/services/DownloadService.ts`
- 单例（`getInstance()`，参照 `ProtocolService`/`TrayService` 模式）。
- 持有当前代理 dispatcher（`ProxyAgent | null`），通过 `setProxy({enabled, url})` 更新：
  - `enabled && url` → `setGlobalDispatcher(new ProxyAgent(url))` + 记录内部引用；
  - 否则 → 恢复默认 dispatcher（`setGlobalDispatcher(new Agent())`）。
  - 同时写入/清除 `process.env.HTTP_PROXY` / `HTTPS_PROXY`（`electron-updater`、`npm` 子进程等读 env 的组件也能受益）。
- 核心方法：
  ```ts
  downloadFile(url, opts?: {
    checksum?: string              // 可选 sha256（支持 'sha256:xxx' 前缀）
    signal?: AbortSignal           // 取消
    onChunk?: (byteLen: number) => void  // 进度回调
  }): Promise<Buffer>
  ```
  - 内部 `await fetch(url, { signal })`（因全局 dispatcher 已是 ProxyAgent，自动走代理，无需显式传 dispatcher）；
  - 流式 `response.body.getReader()` 逐块累加 + `onChunk`，最后 `Buffer.concat`；
  - 校验 sha256（把 `PluginHandler.verifyChecksum` 的逻辑搬过来），不一致抛错。
- 暴露 `setProxy` 给主进程启动时调用。

### 第 3 步：主进程启动时自举代理 + Electron session 同步
**文件**：`packages/mira-client/src/main/main.ts`
- 顶部 import `DownloadService`、`session` from electron、`ConfigStorage`（或直接用 `electron` 的 `app.getPath('userData')` 读 `mira-settings` JSON，避免 ConfigStorage 是渲染层模块的依赖问题——读盘逻辑写成小工具函数）。
- 在 `setupApp()` / `app.whenReady()` 内（L132 附近）：
  1. 读 `mira-settings` 中的 `networkProxyEnabled`/`networkProxyUrl`；
  2. `DownloadService.getInstance().setProxy({enabled, url})`；
  3. `session.defaultSession.setProxy({ proxyRules: enabled && url ? url : 'direct://' })`，渲染层 `fetch`（含 `fetchMarketplaceCatalog`）自动走代理。

### 第 4 步：新建 `network:set-proxy` IPC handler
**新文件**：`packages/mira-client/src/main/handlers/NetworkHandlers.ts`
- 注册 `ipcMain.handle('network:set-proxy', (_, cfg) => DownloadService.getInstance().setProxy(cfg))`，返回 `{success: true}`。
- 顺带 `ipcMain.handle('network:test-proxy', ...)` —— 见第 5 步。
- 在 `IPCHandlers`（`handlers.ts` L37–69）实例化它，在 `removeAllHandlers`（L174）补 `ipcMain.removeHandler('network:set-proxy'/'network:test-proxy')`。

**文件**：`packages/mira-client/src/preload/preload.ts`
- 在 `electronAPI` 新增 `network` 块：
  ```ts
  network: {
    setProxy: (cfg: { enabled: boolean; url: string }) =>
      ipcRenderer.invoke('network:set-proxy', cfg),
    testProxy: (cfg: { enabled: boolean; url: string }) =>
      ipcRenderer.invoke('network:test-proxy', cfg),
  },
  ```

**文件**：`packages/mira-client/src/shared/types.ts`
- 在 `ElectronAPI`（L387）加 `network` 接口定义，匹配 preload。

### 第 5 步：代理测试功能（主进程 fetch 探测）
在第 4 步的 `network:test-proxy` handler 里实现：
- 临时 `setGlobalDispatcher(new ProxyAgent(url))`；
- `fetch(testUrl, { signal: AbortSignal.timeout(8000) })`（用一个稳定目标，如配置的市场源 `/plugins.json` 或回退到 `https://www.google.com/generate_204`）；
- 返回 `{ success: ok, statusCode, elapsedMs, message }`；
- finally 恢复原 dispatcher。
- 这样无论是否已「保存」配置，用户都能先「测试」当前输入框中的代理地址。

### 第 6 步：`PluginHandler` 改用 `DownloadService`
**文件**：`packages/mira-client/src/main/handlers/PluginHandler.ts`
- 构造时持有 `this.downloader = DownloadService.getInstance()`。
- 把 `downloadAndVerifyFile`（L585–619）改为委托 `DownloadService.downloadFile(url, { checksum, signal, onChunk })`，保留方法签名不变，调用点（L733、L752、L772）零改动。
- 删除 `verifyChecksum`（L624）——逻辑移入 `DownloadService`；若 PluginHandler 别处复用则保留薄封装转调。

> 这一步满足「PluginsDialog 里的下载插件要通过这个方法去下载文件」：插件下载链路 `PluginsDialog → pluginStore.installMarketplacePlugin → PluginService.installMarketplacePlugin → IPC plugin:install-from-marketplace → PluginHandler.handleInstallFromMarketplace → DownloadService.downloadFile`，统一经由新下载 API 且自动走代理。`PluginsDialog.vue` 自身无需修改。
