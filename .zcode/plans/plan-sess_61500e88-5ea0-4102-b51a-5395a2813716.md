## 目标
在 `MediaTabListView.vue` 底部状态栏右侧新增一个「眼睛」图标按钮，点击弹出 popover（checkbox list，5 项：文件名 / 格式 / 大小 / 文件夹 / 标签）。勾选状态控制三个视图（grid / waterfall / list）下每个媒体项展示哪些信息字段。

## 设计决策（已与用户确认）
- **存储位置**：全局 `AppSettings.visibleItemFields`（数组）。与 `columnsPerRow` / `videoPreviewMuted` 一致，通过 `updateSetting` → `saveSettings` → ConfigStorage 自动持久化；新字段对老用户向后兼容（load 时浅合并默认值）。
- **网格 / 瀑布流卡片**：紧凑信息行 —— 文件名为标题，下方一行用 `·` 拼接勾选的元信息（格式·大小·文件夹），再一行标签 chips。
- **列表视图**：字段映射为列 —— 文件名/格式/大小/文件夹/标签各自成列，未勾选则隐藏该列；保留现有 预览/分辨率/创建时间/操作 列。

## 字段定义
`type ItemField = 'filename' | 'format' | 'size' | 'folder' | 'tags'`
默认全部勾选：`['filename','format','size','folder','tags']`。

## 实现步骤

### 1. 设置层 — `packages/mira-client/src/renderer/stores/settings.ts`
- `AppSettings` 接口新增：`visibleItemFields: ItemField[]`
- 默认值对象新增（在 `videoPreviewMuted` 附近）：`visibleItemFields: ['filename','format','size','folder','tags']`
- `resetSettings()` 的 `defaultSettings` 对象内同步新增同一默认值（否则 reset 会缺字段）
- 复用现有 `updateSetting('visibleItemFields', next)` 持久化，无需新增 setter

### 2. 顶部状态栏触发器 — `MediaTabListView.vue`
在 `<footer>` 右侧 `<div class="flex items-center space-x-4">`（约 199 行）内、列数滑块后新增：
- 用现有 `Dropdown`（`placement="top-end"`, `closeOnContentClick` 保持默认 false → 切 checkbox 不关闭，符合 FilterBar 同款模式）
- trigger 为眼睛图标按钮（`material-icons` + `visibility`），class 沿用文件内既有小图标按钮样式（`bg-white/40 dark:bg-muted/60 backdrop-blur` 等）
- `#content` 内为 `<label>` + `Checkbox`（`@/components/ui/checkbox`）列表，逐项 toggle `settingsStore.settings.visibleItemFields`
- script: 引入 `Checkbox`；读取/写入走 `settingsStore`（文件已 `useSettingsStore`）

### 3. 网格卡片 — `MediaGridComponent/MediaGridItem.vue`
- 引入 `useSettingsStore` + `useFolderStore` + `useTagStore`
- 计算 `visible = settingsStore.settings.visibleItemFields`，并加 `show(field)` 判断
- 重构底部文件名浮层（122-134 行）为紧凑信息块：
  - 第 1 行：文件名（`show('filename')` 时显示）
  - 第 2 行：`format · size · folder` 仅显示勾选项（folder 名通过 `folderStore.getFolderById(Number(item.folderId))?.title || '未分类'` 解析）
  - 第 3 行：标签 chips（`show('tags')` 且 `item.tags?.length` 时，逐个 `tagStore.tags.find(t => String(t.id) === String(id))?.title || id`）
- 左上角格式徽章（62-68 行）：受 `show('format')` 控制（未勾选则隐藏），与信息行一致
- 选中态背景保持不变

### 4. 瀑布流卡片 — `WaterfallComponent/MediaWaterfallItem.vue`
与网格卡片完全一致的改造（同三个 store、同 helpers、同紧凑信息块结构、同左上角徽章控制）。底部浮层在 135-147 行、左上角徽章在 73-79 行。

### 5. 列表视图 — `MediaListComponent.vue`
- 引入 `useSettingsStore` + `useFolderStore` + `useTagStore`，计算 `visible`
- 列调整：
  - 现有「文件名」列（含格式徽章）：拆分 —— 文件名列只显示名称（`show('filename')` 控制整列），格式徽章移到独立的「格式」列（`show('format')` 控制整列）
  - 现有「大小」列：受 `show('size')` 控制
  - 新增「文件夹」列：`show('folder')` 时显示，内容为 folder 名（store 解析），无 folder 显示 `-`
  - 新增「标签」列：`show('tags')` 时显示，内容为标签 chips（取前 3 个 + `+N`）
- 表头 `TableHeader` 与 `TableBody` 两处同步增删/受控
- 预览 / 分辨率 / 创建时间 / 操作 列保持不变

## 关键复用点（不重复造轮子）
- `Dropdown`（`@/renderer/components/common/Dropdown`，默认不关闭）— FilterBar 已用同款
- `Checkbox`（`@/components/ui/checkbox`）— MediaListComponent/FolderEditDialog 已用
- `settingsStore.updateSetting` — 持久化路径，与 `videoPreviewMuted` 同
- folder/tag 解析：直接 `folderStore.getFolderById` + `tagStore.tags.find`（**不**复用 MediaDetailComponent 里那个有 bug 的 `getFolderName` 占位实现）

## 不在本次范围
- 不新建 `useDisplayNames` composable（三个组件直接用 store，避免过度抽象；若后续复用增多再抽）
- 不改文件信息侧边栏（MediaDetailComponent）的展示
- 不做 per-tab 差异化（全局统一，与 columnsPerRow 一致）

## 验证方式
- 启动 client，进入媒体 Tab，底部出现眼睛图标
- 点击弹出 5 项 checkbox，切换后 grid/waterfall/list 三视图实时响应
- 刷新 / 重开 app，勾选状态保留（持久化生效）
- 切到回收站 Tab 同样生效
