## 批量下载文件功能实现计划

### 后端（mira-app-server）

**1. 安装依赖**（`packages/mira-app-server`）
```
npm install archiver @types/archiver
```
`archiver` 是 Node.js 标准流式 zip 库，原生支持 `archive.pipe(res)`，契合现有 `createReadStream().pipe(res)` 风格。

**2. FsRouter.ts 新增 `POST /fs/download` 路由**
- 入参：`{ libraryId: string; paths: string[] }`
- 复用 `getLibraryPath()` + 路径穿越校验（与 list/move/remove 完全一致，`FsRouter.ts:107/177/210`）
- 解析所有 paths 为绝对路径，过滤掉越权路径；空则返回 400
- **单文件**：直接 `fs.createReadStream().pipe(res)`，`Content-Disposition: attachment`（与 `FileRoutes.ts:556` 一致）
- **多文件 / 含目录**：用 `archiver` 流式打 zip，`archive.pipe(res)`，递归打包目录
- 退出前 `archive.finalize()`；error 事件兜底 500
- 不落临时文件，全程流式，零额外磁盘占用

**3. HttpServer.ts**：路由已挂载 `/api/fs`（HttpServer.ts:312），新增子路由无需额外挂载

### 前端（mira-dashboard-next）

**4. fileManager.ts 新增 download 方法**
```ts
download: (data: { libraryId: string; paths: string[] }) =>
  client.post('/fs/download', data, { responseType: 'blob' }),
```

**5. index.vue 新增批量下载**
- 新增 `downloading` ref + `batchDownload()` 函数：
  - 调 `fileManagerApi.download`
  - 从 `res.headers['content-disposition']` 解析文件名（正则），失败默认 `download.zip`
  - `Blob` + `URL.createObjectURL` + 隐藏 `<a>` 触发下载 + `revokeObjectURL`
  - toast 失败提示
- 在批量按钮组（移动与删除之间）插入「下载」按钮：
  - `v-if="selected.size > 0"`，`variant="outline"`，`size="sm"`
  - 图标 `RiDownloadCloud2Line`（已 import）
  - loading 时显示 spinner
- 放置顺序：移动 → **下载** → 删除（破坏性操作置末）

**6. i18n**（zh-CN/en-US 的 views.json）
- 新增 `fileManager.downloadBatch`：「批量下载 / Batch Download」

### 边界处理
- 单文件直接下原文件，不打包（符合"多文件才打 zip"）
- 选中含目录时，目录递归进 zip
- 路径穿越：全部沿用 FsRouter 现有 `startsWith(basePath)` 校验
- 文件名编码：`encodeURIComponent` + 前端 `decodeURIComponent` 解析

### 验收（实施后）
1. 选中单个文件 → 点下载 → 浏览器直接下原文件
2. 选中多个文件 → 点下载 → 下到 `download.zip`，解压含全部文件
3. 选中含目录 → 解压后目录结构完整
4. 未选中时按钮不显示
5. 按 AGENTS.md：未改 mira-app-core 故无需 build core；新装依赖后用 procm-mcp 重启 mira-app-server
