## 插件市场 (客户端) 方案 — 修订版 (HTTP 静态服务)

### 核心模型修正
`online_client_plugins/` 是**源仓库**, 内容通过**静态 HTTP 服务**对外提供 (如 nginx / GitHub Pages / `npx serve` 指向该目录)。客户端**不打包**它, 运行时 fetch 远程 `plugins.json` 拉目录, 选中插件后从远程下载到本地 `pluginsDirectory`, 复用已有本地插件加载流程。

不再修改 `electron-builder.json`。

---

### 设计决策 (合理默认)
- **市场源地址 = 用户可配置**, 默认空。新增 settings 字段 `clientPluginMarketUrl`。设置页加输入框, 留空则市场 Tab 显示"未配置市场源"。这样开发/自建/官方源都能用, 且无需硬编码任何地址。
- **下载 = 单文件 HTTP 流式写入** (主进程 `fetch` + `fs`), 落地到 `pluginsDirectory/<pluginId>/`, 跟手动放目录等价。简单可靠, 先不做 zip/增量。
- **目录位置 = `D:/mira_typescript/online_client_plugins/`** (项目根, 与服务端 `plugins/` 平级, 名字带 client 防混淆)。

> 两处未答复的澄清问题用以上默认值, 互不耦合, 可后续调整。

### 第一部分: 新建 `online_client_plugins/` 源目录

      "category": "development",

      "readme": "README.md" | null,

      "checksum": "sha256:..."
    }

`README.md` 说明两种起服务方式: `npx serve online_client_plugins -p 8080` 或 nginx, 并强调 `plugins.json` 必须在根、CORS 允许客户端域。

### 第二部分: 索引生成脚本 (自动更新)

新建 `scripts/build-client-plugins-index.mjs` (Node ESM, 零依赖, 跨平台):
- 扫描 `online_client_plugins/plugins/*/` 下含 `plugin.json` 的目录
- 校验 `pluginId`/`pluginName`/`version` (复用 `PluginHandler.validatePluginConfig` 同款规则), 检测 `pluginId` 重复
- 计算 `size` (递归 stat) 与 `checksum` (sha256: 按相对路径 Unicode 排序, 对每文件 `path\0content` 累加哈希, 保证可重现)
- 原子写回 `plugins.json` (写 `.tmp` 再 rename)
- 有错误退出码非零, 输出统计; 支持 `--watch` 开发时自动重建
- 文件清单 (递归) 也写进每个 entry, 供客户端逐文件下载校验

在**根 `package.json`** `scripts` 加:
```json
"build:client-plugins-index": "node scripts/build-client-plugins-index.mjs",
"dev:client-plugins": "node scripts/build-client-plugins-index.mjs --watch"
```

### 第三部分: 类型定义 (`shared/types.ts`)

```ts
export interface MarketplacePluginFile { path: string; size: number; checksum: string }

export interface MarketplacePluginEntry {
  pluginId: string; pluginName: string; version: string
  description: string; author: string; homepage?: string
  category?: string; tags: string[]
  minAppVersion?: string; platform?: string[]
  directory: string          // 相对市场根
  icon?: string | null
  readme?: string | null
  size: number               // 目录总字节
  checksum: string           // 整目录哈希
  files?: MarketplacePluginFile[]
}

export interface MarketplaceCatalog {
  version: number; generatedAt: string
  plugins: MarketplacePluginEntry[]
}
```

`ElectronAPI.plugin` 接口追加 (主进程负责下载, 避免渲染进程 CORS/大文件):
```ts
installFromMarketplace: (marketUrl: string, entry: MarketplacePluginEntry) => Promise<BaseResponse>
```
> catalog 直接由**渲染进程 fetch** (`PluginService.http` 已是现成模式, 无需走 IPC); 下载因涉及写 `pluginsDirectory` 必须主进程做。

### 第四部分: 主进程 — `PluginHandler` 扩展

新增 1 个 handler `plugin:install-from-marketplace`:
- 入参 `marketUrl` (源根) + `entry`
- 目标 `pluginsDirectory/<pluginId>/` (存在则提示先卸载或覆盖)
- 用 entry.files 逐文件下载: `${marketUrl}/${entry.directory}/${file.path}`, 流式写入, 校验 sha256; 无 files 列表则退化为递归下载目录 (读 plugin.json 推断 index 等必要文件)
- 完成后 `discoverPlugins()` 验证 `plugin.json` 可解析
- 返回 `{ success, data: { directory, config } }`

`getMarketplaceDir` 等本地路径相关逻辑**全部移除** (不再需要)。
`cleanup()` 加对应 `ipcMain.removeHandler`。

### 第六部分: 渲染层

**`PluginService.ts`**:
- `fetchMarketplaceCatalog(url)` → `fetch(url.replace(/\/$/, '') + '/plugins.json')`, 解析为 `MarketplaceCatalog` (复用 `createPluginContext` 里的 fetch 模式, 非 Electron 环境也能用)
- `installMarketplacePlugin(url, entry)` → 转发 IPC, 成功后内部调 `discoverLocalPlugins()` 刷新

**`stores/plugin.ts`**:
- 新增 `marketplaceCatalog = ref<MarketplacePluginEntry[]>([])`, `marketplaceUrl` (读自 settings)
- `fetchMarketplaceCatalog()` action, `installMarketplacePlugin(entry)` action (用现有 `wrappedWithOperation` + `pendingOperations`)

**`stores/settings.ts`**: `Settings` 接口 + 默认值加 `clientPluginMarketUrl: ''`。

**设置页** (`packages/mira-client/src/renderer/views/settings/`): 加一个"插件市场源"输入框, 持久化到 settings。
