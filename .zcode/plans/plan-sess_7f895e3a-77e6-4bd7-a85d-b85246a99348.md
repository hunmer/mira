## 设计分析（基于 emil-design-eng skill）

按 skill 的「动画决策框架」逐一过：

**频率**：搜索栏展开/折叠、文件夹展开/折叠都属于「一天几十次」的侧栏交互，且文件夹展开是点击触发（非键盘），所以**可以做动效，但必须短、利索、不打断节奏**。

**用途**：状态指示（文件夹是否展开）+ 防止突变（搜索框/子节点突然出现/消失）—— 都是正当目的。

**时长**：150–250ms（dropdown/expand 范围），UI 动画绝不超 300ms。

**缓动**：用强 ease-out `cubic-bezier(0.23, 1, 0.32, 1)`（这正是本仓库 `main.css` 第 55 行已经在用的曲线，保持一致性）。展开是「进入」→ ease-out；颜色/hover → ease。

**关键约束（必须说明）**：`@he-tree/vue` 折叠时是把子节点从 `visibleStats` 列表里直接过滤掉（`index.mjs:269` 的 `t.filter((a) => n(a))`），子 DOM **立即消失**。因此「折叠时子容器高度收缩」在纯 CSS 层面做不了（容器本身没了）。可做且干净的动效点只有两个：① **chevron 图标旋转** ② **展开瞬间子节点淡入上滑（stagger）**。强行做 height 折叠需要包一层 wrapper 拦截 open 时机，复杂且与拖拽/虚拟列表冲突，不值得——这次不做。

## 实施方案

### 改动 1：搜索栏展开/折叠动效（核心，纯 CSS）

把 `<div v-if="showSearch" ...>`（第 106 行）包进 Vue 内置 `<Transition name="search-slide">`，用 **`grid-template-rows: 0fr → 1fr`** 技巧做高度过渡（不需 JS 测量高度，且 `@media (prefers-reduced-motion: reduce)` 下自动失效）。

- 包裹一层 `<div class="search-shell">`，`display: grid; grid-template-rows: 0fr`，展开时 `1fr`
- 内层 `<div style="overflow: hidden">` 包住原来的 input 容器
- 配合 `opacity 0→1` + 微小 `translateY(-4px)→0`，ease-out 200ms
- 入场快（200ms ease-out），出场更快利索（150ms）—— 符合 skill「release 快」原则
- `v-if` 改为 `v-show` 不行（需 enter/leave 钩子），保留 `v-if` + `<Transition>`

### 改动 2：文件夹 chevron 旋转动效

把第 153-155 行 / 190-192 行两个图标的**双图标切换**改为**单图标旋转**：
- 统一用 `chevron_right`（Material），`stat.open` 时 `transform: rotate(90deg)`
- `transition: transform 200ms cubic-bezier(0.23, 1, 0.32, 1)`
- `transform-origin: center`（chevron 是独立小图标，不像 popover 需锚定触发点）
- 旋转比图标切换更平滑、更 macOS Finder

### 改动 3：展开时子节点淡入（轻量装饰，可选）

skill 的 stagger 思路：给 `.tree-node-inner` 加一个轻量入场 `@keyframes`（opacity 0→1 + translateY(4px)→0，150ms），让展开瞬间子节点不是「砰」地出现。用 CSS animation + 延迟微调。**但** he-tree 节点是复用的（v-for 复用 DOM），animation 会在初次渲染和切换时都触发——这点要在实现时验证，若副作用（如折叠后再展开节点闪烁）明显则回退掉，只保留改动 1+2。

### 改动 4：按下反馈（skill 必备项）

chevron 和搜索按钮加 `:active { transform: scale(0.9) }`（图标按钮用 0.9 比卡片按钮更克制），`transition: transform 160ms ease-out`。

## 评估表格（skill 要求格式）

| Before | After | Why |
| --- | --- | --- |
| `v-if="showSearch"` 无过渡，框瞬间出现/消失 | `<Transition>` + `grid-template-rows: 0fr→1fr` + opacity，200ms ease-out 进 / 150ms 出 | 防止突变；进入用 ease-out 有 punch，退出更快利索 |
| chevron 在 `expand_more`↔`chevron_right` 两图标间切换（无过渡） | 单 `chevron_right` + `rotate(90deg)`，200ms 强 ease-out | 旋转平滑、连续，比图标切换更像 Finder/macOS |
| chevron / 搜索按钮无 `:active` 反馈 | `:active { transform: scale(0.9) }` 160ms ease-out | skill 硬性项：按下必须给即时反馈 |
| 折叠时子节点瞬间消失（库行为，无法纯 CSS 收缩高度） | 仅给展开入场加轻量淡入（150ms）；折叠保持库原生行为 | 库折叠即移除 DOM，硬做高度动画会与拖拽/虚拟列表冲突，不值得 |

## 改动范围
仅 `FolderTreeComponent.vue`：
- template：搜索框外包 `<Transition>` + grid 容器；chevron 改单图标旋转
- `<style scoped>`：新增 `.search-shell`、`.search-slide-enter/leave-*`、`.folder-chevron`、`:active`、（可选）子节点淡入 keyframes
- 无 JS 逻辑改动、不动 props/emits、不新增依赖

## 不做的事（skill 取舍）
- 不做 height 收缩折叠动画（库限制，强行做收益<成本）
- 不动 `transition-colors` 等已有项
- 不加 `prefers-reduced-motion` 单独分支：`grid-template-rows` 过渡 + transform 在 reduced-motion 下浏览器原生不会剧烈位移，且 he-tree 默认 CSS 第 1 行已有 `@media (prefers-reduced-motion: reduce){ .he-tree *{ transition:none!important } }` 兜底；搜索框那层会补一条 reduced-motion 降级（只留 opacity、去掉高度动画）
