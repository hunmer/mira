## 总览

7 项需求,逐项给出根因/做法。已确认的关键事实:
- `maxurl.user.js`(14 万行 IIFE)在浏览器有 `window` 时**不走** `module.exports`,但会把 `bigimage_recursive` 赋给全局 `$$IMU_EXPORT$$`(L127385),函数签名 `bigimage_recursive(url, {cb, do_request, filter, fill_object, ...})`,`cb(result[])` 收 `{url, is_original, bad, fake, video}`。Eagle 的调用模式(`index.ts:608-654`)可直接借鉴。
- `FOLDER_LIST` 消息 → `client.folders().getAll(libraryId)` 返回 `Folder[]`,已具备。
- `contextMenus` 权限已开;`libraryId`/`folderId`/`tags` 已在 settings 持久化。
- Vite 内置 `?raw` 可把 maxurl 当文本取,再封装暴露。

## 需求 5:接入 maxurl.user.js 前端提取高清大图

> 用户已选:本地内置。

- 拷贝 `plugins/plugins/mira_eagle_extension/maxurl.user.js` → `packages/mira-browser-extension/src/vendor/maxurl.user.js`(14 万行,纯文本,不参与 ts 编译)。
- 新建 **`src/shared/imu.ts`** 封装:
  - `import maxurlSource from './vendor/maxurl.user.js?raw'`(Vite `?raw`)。
  - 用 `new Function` 沙箱求值:`new Function('module','exports','window','document','GM_xmlhttpRequest', source)` 之前先 mock `window/document/GM_*` 为极简 stub 或把 source 包一层捕获 `$$IMU_EXPORT$$`。**更稳的做法**:source 末尾追加一行 `;return typeof $$IMU_EXPORT$$ !== 'undefined' ? $$IMU_EXPORT$$ : null;`,用 `new Function(source)()` 拿到 `bigimage_recursive`。
  - `export function upgradeImageUrl(url, {timeout}): Promise<string[]>` —— 仿 Eagle `upgradeImageUrlCandidates`:`imu(url, {fill_object:true, filter, do_request:用 fetch 封装类 GM_xhr, cb})`,过滤 `bad/fake/video`,`is_original` 优先,原 url 保底返回 `[...candidates, url]`。`do_request` 在 content script 里用原生 `fetch` 实现(浏览器环境天然支持,比 Eagle 的 http 模块更简单)。
- **接入点**(`content/dragdrop.ts` onUpload 与 `message-router` 的 `UPLOAD_FROM_URL`):
  - 拖图/嗅探/右键上传图片时,先 `upgradeImageUrl(src)`,拿到候选 URL 列表,service worker 依次尝试下载直到成功(逐个 fetch,blob 非空即用)。maxurl 调用在 content script(有完整 DOM/GM-less 环境),把升级后的 URL 传给 service worker。
  - 加设置开关 `imuEnabled`(默认 true)放设置页;关闭则直接用原 URL。
- 风险:maxurl 体积大(增大 dist,可接受,离线优先)。eval/`new Function` 受 MV3 CSP 约束——MV3 内容脚本允许 `new Function`(不是远程脚本),验证若不行则改用 `<script>` 注入页面世界读 `$$IMU_EXPORT$$`。**实现时先验证 CSP,作为首要风险点。**
