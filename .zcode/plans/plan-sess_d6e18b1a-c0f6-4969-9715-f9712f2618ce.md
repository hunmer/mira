## 目标
将 `MediaGridComponent` 现有的右键菜单（逻辑 + UI）抽取为一个可复用的包装组件 `MediaContextMenu.vue`，让 `MediaListComponent` 和 `WaterfallComponent` 通过包裹它获得完全相同的右键菜单（查看信息 / 复制JSON / 插件 / 设置文件夹 / 设置标签 / 定位 / 删除 / 恢复）。

## 核心发现（为什么这样设计可行）
- `composables/useContextMenu.ts` **已经是视图无关**的：入参仅 `{ items, selectedItems, isTrash }` + emit，内部执行删除/恢复/设置文件夹/设置标签的副作用，并 emit 事件供父级刷新。可直接复用，无需改动其逻辑。
- 三个视图的每个条目都已打上 `data-selectable-id` 属性（SelectionBox 要求），所以包装组件可以通过 `event.target.closest('[data-selectable-id]')` **自行解析右键命中的条目**，父组件无需做任何额外的事件转发来"告知命中了哪个条目"。
- 当前网格就是用 reka-ui 的 `<ContextMenu>` + `<ContextMenuTrigger as-child>` 包裹内容区，菜单内容模板约 100 行 + 两个 Popover（文件夹/标签选择）。这些全部可整体搬进包装组件。

## 实施步骤

### 1. 新建 `MediaContextMenu.vue`（核心）
位置：`packages/mira-client/src/renderer/components/business/MediaContextMenu.vue`

职责：
- Props：`items: FileInfo[]`、`selectedItems: string[]`、`isTrash?: boolean`
- Emits：`media-context-menu`、`media-info`、`media-set-folder`、`media-set-tags`、`media-delete`、`media-restore`（与 `useContextMenu` 的 emits 完全一致）
- 内部调用 `useContextMenu(props, emit)`，拿到 `contextMenuItems`、`handleContextMenu`、popover 状态/数据等
- 模板：
  - `<ContextMenu>` 包裹整体
  - `<ContextMenuTrigger as-child>` 包裹 **默认 slot**（即各视图的真实内容区）
  - 在 trigger 元素上加 `@contextmenu.capture="resolveAndOpen"`：通过 DOM 查询命中 `data-selectable-id` → 从 `props.items` 取出 item → 调用 composable 的 `handleContextMenu(item, event)` 设置 `currentContextItem` 并 emit `media-context-menu`。reka-ui 随后自动打开菜单
  - `<ContextMenuContent>` 渲染递归菜单项（原样从 MediaGridComponent 搬迁：Separator / Sub / 递归 Sub / Item，含 `executeMenuCommand`）
  - 内嵌两个 `<Popover>`（文件夹选择 + 标签选择，绑定 `folderPopoverOpen` / `tagPopoverOpen` / `popoverPosition`），以及 `FolderTreeComponent`
- 暴露 `executeMenuCommand`（菜单项命令执行器，内部捕获异常）

这样三个视图只需各自包裹一次，行为天然统一。

### 2. 重构 `MediaGridComponent/MediaGridComponent.vue`
- 删除模板里的 `<ContextMenu>...<ContextMenuContent>` 整块和两个 `<Popover>`（约 100 行），改用 `<MediaContextMenu :items="props.items" :selected-items="props.selectedItems" :is-trash="props.isTrash" @media-...="...">` 包裹原来的 grid `<div>`
- 转发 MediaContextMenu 的 6 个 emit 给上级（保持现有 emit 契约不变）
- 不再直接 import/use `useContextMenu`、`ContextMenu*`、`Popover*`、`FolderTreeComponent`、`MenuItem`（这些都收进包装组件）
- `handleContextMenu`（原 contextMenuHandler 转发）随 composable 一并移出，MediaItem 的 `@context-menu` 事件链可保留（无害）或一并简化——优先保留以减少行为变化

### 3. 改造 `MediaListComponent.vue`
- 在 `<SelectionBox>` 内部，用 `<MediaContextMenu :items :selected-items :is-trash @media-...>` 包裹 `<Table>`（trigger=Table，as-child 合并到 `<table>`）
- 新增 `isTrash?: boolean` prop 并透传
- Emits 接口补齐：移除原生 `contextmenu` 的 emit，改为转发包装组件的 `media-context-menu`、`media-info`、`media-set-folder`、`media-set-tags`、`media-restore`（与网格对齐）；保留现有 `click` / `dblclick` / `preview` / `media-select` / `media-delete`
- TableRow 上的 `@contextmenu="emit('contextmenu', ...)"` 改为不再需要（由包装组件接管）；保留 `.prevent` 由包装组件 trigger 处理

### 4. 改造 `WaterfallComponent.vue`
- 在 `<SelectionBox>` 内部，用 `<MediaContextMenu>` 包裹 `<Masonry>`（trigger=Masonry，合并到其根元素）
- 新增 `isTrash?: boolean` prop 并透传
- Emits 接口同列表：转发 `media-context-menu` 等 6 个事件；`handleItemContextMenu` 不再 emit 原生 `contextmenu`（交给包装组件）

### 5. 同步父级绑定（让事件链真正接通刷新逻辑）
- **`MediaTabListView.vue`**：给 `<MediaListComponent>` 与 `<WaterfallComponent>` 的绑定补齐为与网格一致——`:is-trash="viewType === 'trash'"`、`@media-context-menu="handleMediaContextMenu"`、`@media-info="handleMediaInfo"`、`@media-set-folder="handleMediaSetFolder"`、`@media-set-tags="handleMediaSetTags"`、`@media-delete="handleMediaDelete"`、`@media-restore="handleMediaRestore"`；移除已失效的 `@contextmenu` / `@preview` / `@download` 旧绑定（保留仍有意义的）
- **`MediaContentView.vue`**：同样把列表/瀑布流的绑定补齐到与网格一致（`@media-context-menu` 等）

## 风险与兜底
- **reka-ui `as-child` 合并到组件根**：网格已验证可行（合并到普通 div）。列表的 `<Table>`、瀑布流的 `<Masonry>` 同为单根。若 `as-child` 合并到 `<table>` 或 Masonry 根出现异常，兜底方案是在包装组件外再套一层透明 `<div>` 作为 trigger（对网格无影响，因为默认 slot 仍是单根）。
- **时序**：`currentContextItem` 在 trigger 的 `contextmenu.capture` 阶段同步设置，早于 reka-ui 打开菜单与菜单内容渲染，菜单首屏即可拿到正确目标条目。
- **回收站视图**：`useContextMenu` 已有 `isTrash` 分支（恢复/彻底删除）。给列表/瀑布流传 `isTrash` 后，它们在回收站视图下也能显示正确菜单，不再误显示"删除"。

## 影响范围
- 新增 1 文件：`MediaContextMenu.vue`
- 修改 5 文件：`MediaGridComponent/MediaGridComponent.vue`、`MediaListComponent.vue`、`WaterfallComponent.vue`、`tabs/MediaTabListView.vue`、`MediaContentView.vue`
- `useContextMenu.ts` **不改动**（纯复用）
- 不改 SelectionBox、不改 MediaItem 子组件、不改后端

## 验证
- 三种视图（grid/list/waterfall）右键单条与多选时，菜单项、计数文案（如"删除 (N)"）、设置文件夹/标签的 Popover、查看信息、定位文件夹、删除/恢复行为完全一致
- 回收站视图下，三种视图均显示"恢复 / 彻底删除"
- 删除/恢复后父级正常刷新（事件链接通）
