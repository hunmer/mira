# 拆分 LoginView.vue 为多文件

## 背景

`packages/mira-client/src/renderer/views/LoginView.vue` 当前为 712 行的单文件组件（SFC），包含三个步骤的 UI（服务器连接 / 认证 / 素材库选择）+ 部署指南对话框，以及全部业务逻辑（健康检查、登录、注册、连接素材库等）。

代码库已有成熟约定：`HomeView/` 就是「视图按功能拆分」的范本——一个 `index.vue` 作为编排层 + 多个 `useXxx.ts` 组合式函数承载逻辑 + 多个 `*.vue` 子组件承载 UI 区域 + 一份 `CLAUDE.md` 导航文档。本次严格遵循该约定，将 `LoginView.vue` 重构为 `views/LoginView/` 目录。

## 验证手段（重构必须保持等价）

- `pnpm --filter mira-client type-check` —— 类型检查通过
- `pnpm --filter mira-client lint` —— ESLint 通过
- 路由 `router/index.ts` 仍懒加载 `../views/LoginView.vue` —— 改为指向 `../views/LoginView/index.vue`，是唯一需要同步修改的外部引用

## 拆分结构（新建 `views/LoginView/` 目录）

### 1. 子组件（UI 区域，props/emits 风格，参照 `HomeHeader.vue`）

每个子组件只负责自身那一段模板的渲染，状态与逻辑通过 props/emits 与父级通信。**不使用** provide/inject（代码库无此惯例）。

| 文件 | 职责 | 关键 props / emits |
|------|------|-------------------|
| `LoginStepper.vue` | 顶部三步进度条（第 19–40 行） | props: `currentStep`、`healthData`；无 emits |
| `ServerStep.vue` | 步骤 1：服务器列表 + 添加表单（第 52–149 行） | props: `loading`/`serverList`/`backendStatus`/`selectedServerId`/`showAddForm`/表单字段等；emits: `quickConnect`/`testConnection`/`openDeleteDialog`/`deleteServer`/`update:showAddForm` 等 |
| `AuthStep.vue` | 步骤 2：登录/注册 Tab 表单（第 152–222 行） | props: `loading`/`healthData`/`showPassword`/`showConfirmPassword`/`credentials`/`registerForm`；emits: `login`/`register`/`back`/`toggle:*` |
| `LibraryStep.vue` | 步骤 3：素材库选择（第 225–258 行） | props: `loading`/`libraries`/`selectedLibraryId`/`userRole`；emits: `update:selectedLibraryId`/`connect`/`back` |
| `DeployGuideDialog.vue` | 部署指南 + 手动指南两层对话框（第 261–306 行） | 无 props（内部自管 `showDeployGuide`/`showManualGuide`） |

### 2. 组合式函数（业务逻辑，参照 `HomeView/useHomeInit.ts`、`useHomeUIState.ts`）

每个 composable 接收所需依赖（stores、共享 refs、回调）作为参数，返回状态与方法。**纯函数 / 无跨模块状态依赖**的逻辑（如后端状态徽标的 class 计算、凭据本地存储）抽成独立工具文件。

| 文件 | 职责 |
|------|------|
| `useBackendStatus.ts` | 后端可用性并发检测：`checkBackendStatus`/`checkAllBackends` + `backendStatusLabel/Class/DotClass`（第 365、410–460 行） |
| `useSavedCredentials.ts` | `mira_saved_credentials` 的 localStorage 存取：`saveCredentials`/`loadCredentials`（第 470–492 行），key 常量一并放入 |
| `useConnectionFlow.ts` | 连接流程核心：`testConnection`/`handleLogin`/`handleRegister`/`fetchLibraries`/`connectToLibrary`/`quickConnect`/`handleStepBack`/`isLibraryAccessible`/`createWsUrl`/`createTempClient`（第 499–667 行），依赖 authStore/libraryStore/serverListStore + 共享的 `healthData`/`userRole`/`authToken` 等 refs |
| `useLoginState.ts` | 聚合共享 UI 状态：`currentStep`/`loading`/`error`/步骤 1·2·3 的表单字段与开关（第 349–369、462–468、494–496 行），供 `index.vue` 分发给子组件 |

> 说明：`useConnectionFlow` 之间高度耦合（共享 `tempClient`、`userRole`、`authToken`），合并为单文件而非进一步拆分，避免循环依赖；这与 HomeView 把强相关逻辑归到 `useHomeTabManagement` 的做法一致。

### 3. 编排层

`index.vue`（替代原 `LoginView.vue`）：
- 仅负责：stores 初始化、调用上述 composables、把状态与方法通过 props/emits 接线到子组件、`onMounted` 初始化、`handleClose`、错误横幅、Aurora 背景、`Motion` 容器、关闭按钮
- 保留全部 `<script setup>` 顶层 imports（UI 组件库），子组件通过相对路径 `./Xxx.vue` 引入

### 4. 路由更新

`packages/mira-client/src/renderer/router/index.ts:108`：`'../views/LoginView.vue'` → `'../views/LoginView/index.vue'`

### 5. 文档

新建 `views/LoginView/CLAUDE.md`，更新 `views/CLAUDE.md`（`LoginView.vue` 一行 → 指向 `LoginView/CLAUDE.md`），与 HomeView 的文档结构对齐。

## 执行顺序

1. 新建 `views/LoginView/` 目录及 5 个子组件 `.vue`（从原模板切分，props/emits 接口）
2. 新建 4 个 `useXxx.ts` composable（从原 `<script setup>` 切分）
3. 新建 `index.vue`（编排层）
4. 删除旧 `LoginView.vue`
5. 更新 `router/index.ts` 引用路径
6. 新建/更新 CLAUDE.md
7. 跑 `type-check` + `lint`，按报错微调（props 透传、类型签名）

## 不做的事

- 不改变任何用户可见行为与样式（class、文案、交互完全等价）
- 不引入 provide/inject、不引入 Pinia 新 store、不调整既有 stores
- 不动 `DeploymentChecklist.vue` / `ManualDeployGuide.vue` 等既有业务组件
- 不重命名外部已引用的符号（`LoginView` 仅作为路由组件名保留在 index.vue 的 `defineOptions`）
