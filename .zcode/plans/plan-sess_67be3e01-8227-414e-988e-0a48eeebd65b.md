# 通知 BrowserWindow 窗口 + 通用浮动窗口模板（搜索窗口一并迁移）

## 架构现状与关键发现

通过对 `search-window` 的完整阅读，理清了三层架构，新方案将沿用并抽象它：

1. **主进程层** — `SearchWindowHandlers.ts`：创建透明无边框置顶 `BrowserWindow`，`MessageChannelMain` 双向通信，位置硬编码为屏幕中心。
2. **Preload 层** — `search-preload.js`：把 IPC `connect` 桥接为带 `MessagePort` 的 DOM `MessageEvent`。
3. **渲染层** — 独立 `search-window.html` + `search-window.js`（全局 Vue 挂载，非主 renderer）。开发/生产均用 `loadFile`，不依赖 dev server。

**发现两个既有问题（方案会顺手修复）**：
- `vite.search-window.config.ts` **没有任何 npm script 调用它**，`build:all` 只 build renderer/main/preload。
- `dist-search/` **不在** `electron-builder.json` 的 `files` 数组里 → 生产环境 `dist-search/search-window.html` 路径会找不到文件。新建 notification 窗口若沿用同模式会重蹈覆辙。

## 用户决策（已确认）
- **范围**：抽取通用模板，搜索窗口 + 通知窗口都迁移复用。
- **内容形式**：结构化字段 + 可选任意 HTML（`{title, body, icon, type, actions, html?}`）。

## 实施步骤

### 1. 抽取通用主进程基类 `FloatingWindowHandler.ts`
**新建** `src/main/ipc/FloatingWindowHandler.ts` —— 一个抽象/可实例化的通用浮动窗口管理器，封装现有 `SearchWindowHandlers` 的全部窗口能力：

- `constructor(options: FloatingWindowOptions)`，配置项：
  ```ts
  interface FloatingWindowOptions {
    name: string                       // 'search' | 'notification' | ...
    title: string
    width: number
    height: number
    position?: 'bottom-right' | 'bottom-left' | 'top-right' | 'top-left' | 'center' | 'top' | 'bottom' | { x: number; y: number }  // 默认 'bottom-right'
    margin?: number                    // 距屏幕边缘间距，默认 20
    resizable?: boolean                // 默认 false
    alwaysOnTop?: boolean              // 默认 true
    htmlFileName: string               // 'search-window.html' | 'notification-window.html'
    preloadFileName: string            // 'search-preload.js' | 'notification-preload.js'
    ipcChannelPrefix: string           // 'search-window' | 'notification-window'
    role: string                       // MessagePort role 标识，'search' | 'notification'
    messageHandlers?: Record<string, (data, ctx) => void>  // 各业务自定义消息处理
  }
  ```
- 内置 `createWindow / show / hide / toggle / sendMessage / cleanup / positionWindow` 等公共方法。
- **位置计算独立成 `computePosition()` 方法**，用 `screen.getPrimaryDisplay().workArea` 根据 `position` + `margin` 计算坐标；支持右下角、四角、各边中点、中心、自定义坐标。
- 主题同步、`MessageChannel` 建立、`ready-to-show`、`did-finish-load`、loading 状态等通用逻辑全部上提。
- 业务消息（如搜索窗口的 `search-request`/`open-item`/`drag-file`）通过 `messageHandlers` 回调注入，基类只做转发，`default` 分支转发给主渲染进程（保持现有行为）。

### 2. 改造 `SearchWindowHandlers.ts` 复用基类
将现有 485 行收敛为：实例化 `FloatingWindowHandler`（`position: 'center'`，注入搜索特有的 `messageHandlers`），保留 `forwardResultToSearchWindow` / `forwardMessageToMainRenderer` / `handleDragFile` 等业务方法。**对外 API 完全不变**（`handlers.ts`、`preload.ts` 无需改动），保证搜索功能零回归。

### 3. 新增 `NotificationWindowHandlers.ts`
**新建** `src/main/ipc/NotificationWindowHandlers.ts` —— 基于 `FloatingWindowHandler`（`position: 'bottom-right'` 默认，可在调用时覆盖），额外能力：
- `showNotification(payload)`：支持队列（同时多条通知时堆叠，避免重叠 —— 基类暴露 `positionWindowWithOffset(index)`）。
- 自动消失定时（默认 5s，可配置 `duration`，`0` 表示常驻）。
- `click`/`action` 事件转发给主渲染进程。
- 注册 IPC：`notification-window:show` / `notification-window:hide` / `notification-window:dismiss`。

### 4. 通用渲染层模板 `floating-window/`
**新建** `src/floating-window/` 目录，放可复用的渲染层脚手架：
- `floating-window-core.js` —— 通用工具：MessagePort 建立、主题应用、`drag-start`/`close`/`toggle-devtools` 通用消息、错误展示函数。各窗口页面 import 它。
- `vendor/vue.global.prod.js` —— 复用（从 search-window 移过来，符号链接或拷贝，避免两份）。
- `assets/fonts/material-icons.ttf` 引用路径统一。

### 5. 通知窗口页面 `notification-window/`
**新建** `src/notification-window/`：
- `notification-window.html` —— 主题变量沿用 search-window 风格（深/浅色），通知卡片样式（圆角、阴影、左侧色条按 type 着色：info/success/warning/error）。
- `notification-window.js` —— 全局 Vue 应用：
  - data 接收 `{ title, body, icon, type, actions:[{id,label}], html, duration }`；
  - 结构化字段用 template 渲染；`html` 字段存在时用 `v-html` 渲染到内容区（满足"可选任意 HTML"）；
  - 点击 action → MessagePort 发 `{type:'action', id}`；自动倒计时 → `{type:'dismiss'}`；hover 暂停倒计时。

### 6. 搜索窗口页面迁移到通用模板
改造 `src/search-window/search-window.js`：把 MessagePort 建立、主题、通用快捷键、错误处理等公共部分改为 `import` 自 `floating-window-core.js`，业务搜索逻辑保留。HTML 里的 vendor 路径相应调整。

### 7. 通知窗口 Preload
**新建** `src/preload/notification-preload.js` —— 与 `search-preload.js` 结构一致，`role: 'notification'`，白名单通道换成 `notification-window:*`。

### 8. 构建配置打通（修复既有打包缺陷）
- `vite.search-window.config.ts` → 重命名/扩展为 **`vite.floating-windows.config.ts`**，多入口同时构建搜索窗口和通知窗口到 `dist-float/`：
  ```ts
  input: {
    'search-window': 'src/search-window/search-window.html',
    'notification-window': 'src/notification-window/notification-window.html'
  }
  outDir: 'dist-float'
  ```
- `vite.config.ts` 的 preload 多入口增加 `'notification-preload': 'src/preload/notification-preload.js'`。
- `SearchWindowHandlers` / `NotificationWindowHandlers` 的 `loadFile`/`preload` 路径统一改为 `dist-float/xxx.html` 与 `dist-preload/xxx.js`（dev 仍指向 src 原始文件）。
- **`package.json`**：新增 `"build:float": "vite build --config vite.floating-windows.config.ts"`，并把 `build:all` / `build:prod` 改为包含它。
- **`electron-builder.json`**：`files` 数组增加 `"dist-float/**/*"`（同步把老的 `dist-search` 处理掉，因无残留引用）。这是修复搜索窗口在生产环境加载失败的关键。

### 9. 类型与对外 API
- `src/shared/types.ts`：新增 `notificationWindow` API 类型块：
  ```ts
  notificationWindow: {
    show: (payload: NotificationPayload) => Promise<void>
    hide: () => Promise<void>
  }
  ```
  `NotificationPayload` 含 `position?`、`title`、`body?`、`icon?`、`type?`、`actions?`、`html?`、`duration?`。
- `src/preload/preload.ts`：暴露 `notificationWindow.show/hide` 到主渲染进程，供 `WebSocketService.showDesktopNotification` 等调用方使用（作为增强，不强制替换原生 `Notification`）。
- `handlers.ts`：实例化 `NotificationWindowHandlers` 并在 `removeAllHandlers` 中清理。

## 风险与回滚
- 搜索窗口对外 API 完全不变，回归风险集中在内部基类抽取；若出问题可快速将 `SearchWindowHandlers` 回退为独立实现（git 可恢复）。
- 通知窗口为纯新增，不影响既有功能。
- 构建链改动（build:all + electron-builder files）是修复既有缺陷的正向改动，但需确认打包流程跑通。
